# 테셀레인 아키텍처 개요 (v2 초안)

작성: 윤서하 · 검토: 물류플랫폼팀

## 1. 배경
테셀레인(Tessellane)은 사내 창고 간 배송 순서를 정하는 플랫폼이다. 1차 버전은 단일 PostgreSQL과 cron 배치로 운영했지만,
주문량이 늘면서 스케줄러가 병목이 되었다. 2차 개발의 목표는 조율기(Adaptive Scheduler)를 독립 서비스로 분리하는 것이다.

## 2. 구성 요소
- **조율기**: 작업 큐를 읽어 우선순위를 다시 계산한다. 점수는 리플 랭크(Ripple Rank)에서 받는다.
- **레저 브리지**: 정산 시스템과 배송 결과를 맞춘다. 외부 회계 API와의 경계다.
- **도크 펄스**: 각 창고 도크의 상태를 30초마다 보고하는 에이전트. Grafana 대시보드로 본다.
- 메시지는 Kafka, 캐시는 Redis, 배포는 Kubernetes를 쓴다.

## 3. 처리 흐름
레벨3 파이프라인은 수집 → 정제 → 배정의 세 단계다. 배정 단계에서 조율기가 브레이드 솔버를 호출해 경로를 만든다.
브레이드 솔버의 내부 수식은 이 문서에서 다루지 않는다.

## 4. 운영
나이트 하베스트는 매일 새벽 2시에 전날 주문을 모아 레벨3 파이프라인에 넣는다.
골든 슬롯(오전 9~11시 우선 배송 구간)에 들어간 주문은 조율기가 항상 먼저 처리한다.

## 5. 고객 요구
소라네 로지스틱스의 요구사항 12건 중 9건을 2차 범위에 넣었다. 나머지는 API Gateway 교체 이후로 미룬다.
