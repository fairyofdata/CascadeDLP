# CascadeDLP

[English](README.md) · [한국어](README_KR.md) · [日本語](README_JP.md)

**ローカルモデルが関門に立ち、通ったものだけをクラウドモデルが扱うカスケード型 DLP レイヤー — 韓・日・英の混在文書向け**

GPU 1 枚（RTX 3070 8GB）では最上位モデルの代わりにはなれず、かといってすべてをクラウドに送るわけにもいきません。
CascadeDLP は **ローカルモデルが先に文書を読んで関門判定を行い、通ったものだけをクラウドモデルに渡し、戻ってきた答えをローカルで元の値に戻します。**

## ローカル DLP 関門：検出カスケードと関門判定（基準は機微度）

```
文書 ─▶ ① ローカル関門（規則 + ローカル LLM + 人が確定した用語集）
            │
            ├─ 検出なし ─────────────▶ 原文のまま ──────────────────┐
            ├─ 検出あり ─────────────▶ マスクして（トークンに置換）──┤
            │                                                       ▼
            │                                        ② クラウドモデルが作業
            │                                                       │
            │                                                       ▼
            │                                        ③ ローカルで復元（トークン → 元の値、ファイルへ）
            │
            ├─ 疑わしい ─────────────▶ 送らずにユーザーに確認（ローカルの保留リスト）
            │                           └ 答えると記憶する：保護 → 用語集 / 一般語 → 許可リスト
            ├─ 意味そのものが秘密（L3）─▶ クラウドへ送らずローカルモデルだけで処理（結果はローカルファイル）
            └─ 処理できない ─────────▶ 拒否（秘密鍵、マスクする量が多すぎる、用語集なしで未知の用語が多すぎる）

すべての判定は監査ログに残る（内容なし、ハッシュ・件数・パスのみ）。
```

| 関門判定 | 条件 | 結果 |
|---|---|---|
| **通過**（`cloud_raw`） | 検出なし | 原文のままクラウドへ |
| **マスク**（`cloud_masked`） | 個人情報、用語集の L1・L2 項目 | トークンに置き換えてクラウドへ → 答えはローカルで復元 |
| **確認**（`needs_confirmation`） | 用語集にないがプロジェクト用語らしい語 | 保留。ローカルの保留リストでユーザーが `[x]` 保護 / `[o]` 一般語と印を付ける |
| **ローカル専用**（`local_only`） | 用語集の L3 項目（意味そのものが秘密） | ローカルモデルが処理、結果はローカルファイルにのみ |
| **拒否**（`block`） | 秘密鍵、マスク率 30% 以上、原文にトークン形の文字列、疑わしい項目が多すぎる | どこへも送らない |

### 二つの用語
このプロジェクトでは二つの語が別のものを指します。

- **検出カスケード** — ローカル関門が機微なものを*見つける*やり方。安く確実なものから順に濾す：
  `規則（形式）→ 人が確定した用語集 → ローカル LLM（曖昧なもの）`。前段が捕まえたものを後段は覆せない。
  名前 CascadeDLP の「カスケード」は**これだけ**を指す。
- **関門判定** — 見つけた結果から文書を*どうするか*を決める五つの結論（上の表）：通過・マスク・確認・ローカル専用・拒否。

よく言われる LLM カスケード（安いモデルが先に解き、難しければ高いモデルに回す、性能・コスト最適化）とは**違います。** クラウドに回すかを決める基準は作業の難しさではなく**機微度**です。難しさで回すと「難しくて機微な」文書がクラウドに上がってしまい、DLP と両立しません。

CascadeDLP 自体はクラウドを呼びません。判定結果とマスクしたテキストを呼び出し側（Claude Code など）に返し、クラウドの作業はそちらが行います。

## 約束すること、約束しないこと
**保証装置ではなく、リスクを減らす層です**（[脅威モデル、ADR-0022](docs/adr/0022-threat-model.md)）。

| 約束する | 約束しない |
|---|---|
| 個人情報・顧客名・プロジェクト用語のような**識別子**をマスクして送る（用語集にあれば露出 0） | **「外部持ち出し禁止」方針を満たすこと。** マスクした文書を送るのも持ち出しである |
| 意味が秘密だと指定した（L3）文書は**ローカルに留める** | **意味の保護。** 名前をすべて隠しても「何をどうするか」は原文と同じくらい読める（漏えい 0.89–0.94） |
| 未知のプロジェクト用語が見えたら**止まって尋ねる**（87–93%） | 検出の完全性。個人情報の約 8 件に 1 件、未知の用語の 7–13% は通り得る |
| 何がどこへ行ったかを**記録する** | ソースコード対応（文書のみ）、関門の強制（今は迂回できる） |

このプロジェクトは「マスキングでソースコード持ち出し禁止を越えられるか」から着想しました。作って測った答えは**越えられない**です — コアロジックには隠す基準がなく、隠しても意味が漏れます。意味が秘密なら、答えはマスキングではなくローカル・社内のモデルです。その代わり、持ち出しが許された資料に対するミス防止の層と、何を送るかを決める枠組み（関門判定・用語集・監査ログ）が残ります。

> **現状（2026-10-03）**：文書について上の流れ全体を実装・実測しました。残るのはコードリポジトリ対応（C4）と実文書でのパイロットです（これまでの数値はすべて合成データ）。[ロードマップ](#ロードマップ) · 方向転換の背景 [ADR-0015](docs/adr/0015-cascade-dlp-direction.md)。

**準備段階（プロジェクトごとに一度）**：文書フォルダー → ローカル LLM が**用語集の草案**（このプロジェクトだけの言葉）を作る → 人がチェックしてレベル（L0 公開・L1 名前だけ隠す・L2 トークン・L3 ローカル専用）を決める。関門はこの用語集を基準に判定します。

```text
Tessellane의 조율기는 Ripple Rank 점수를 쓰고 FastAPI 위에서 돈다.          （用語集：L1·L1·L2·L0）
        ↓
[PROJECT_01: 사내 물류 최적화 플랫폼]의 [COMPONENT_01: 작업 우선순위 스케줄러]는 [ALGORITHM_02] 점수를 쓰고 FastAPI 위에서 돈다.
```

### 第 1 段階：個人情報エンティティ（実装済み）
外部 LLM に送る**前に**ローカルで個人情報を `[PERSON_001]` のようなトークンに置き換え、答えが戻ったら**ローカルファイルへ**元の値を戻します。

```text
昨日、한서윤さんと Tanaka Haruto から連絡。ハン・ソユンさんのメールは seoyun.han@example.com
        ↓
昨日、[PERSON_001]さんと [PERSON_002] から連絡。[PERSON_001]さんのメールは [EMAIL_001]
```

## 何が違うか
PII・DLP ツール（Presidio、GLiNER、商用 DLP …）はすでに多くあります。ここでだけ行うこと：

1. **プロジェクト固有の用語を扱う** — `조율기`、`Adaptive Scheduler` のように一般名詞としても使われ規則では捕まえられない語を、人が確定した用語集で表記の揺れ（`adaptive_scheduler`、`適応スケジューラ`）まで見つけてレベル通りに処理する。用語集の草案はローカル LLM が作る。
2. **マスキングの限界を測った** — マスキングは名前を守るが意味（設計意図）は守れないことを数値で確かめ、意味の保護はローカル専用のルーティングで解いた（[ADR-0019](docs/adr/0019-semantic-leakage.md)）。
3. **韓・日・英の混在文書** — 一文の中にハングルの名前、かなの名前、ローマ字が混ざってもよい。
4. **表記をまたぐ連結** — `한서윤 / 韓瑞允 / ハン・ソユン / Seoyun Han` → 同じ `[PERSON_001]`。
5. **長期に安定した可逆の仮名化** — 今日 `[PERSON_001]` だった人は、来週の別の会話でも `[PERSON_001]`。復元は原文と**バイト単位で一致**。
6. **既存ツールを基準線として実測** — GLiNER は空白単位で区切るため日本語の文を丸ごと捕まえるなど、韓・日の文書にそのまま使うのは難しかった（[ADR-0009](docs/adr/0009-gliner-baseline.md)）。

## 設計原則
- **決定論が先、ローカル LLM は形式のないものだけ。** メール・電話・郵便番号・URL・ID の形式は正規表現。LLM は名前・住所・組織名の*候補文字列*と、名前の*ローマ字読み*だけを出す。位置の特定、トークン付与、同一人物の判定、復元はすべてコードが行う（幻覚は原文にないので自動で捨てられる）。
- **呼び出し側は外部 LLM。** MCP ツールは原文を引数に取らず（ファイルパスのみ）、復元結果を返さない（ローカルファイルのみ）。
- **仮名マップはローカルにだけ。** `~/.cascadedlp/` — どのリポジトリにも属さない。
- **開発・評価は合成データのみ。**

## インストール（Windows、Python 3.12+、[Ollama](https://ollama.com)）
```powershell
git clone https://github.com/fairyofdata/CascadeDLP.git
cd CascadeDLP
.\setup.ps1        # venv · 依存 · pip install -e .[mcp] · Ollama モデル · スモークテスト
```

## 使い方
詳しくは [USAGE.md](USAGE.md)（韓国語）。

**CLI**
```powershell
# 1) 用語集を作る（プロジェクトごとに一度、ローカル専用）
cascadedlp --project myproj bootstrap D:\work\myproj\docs      # 候補の確認ファイルを生成
cascadedlp --project myproj apply-review <確認ファイル>          # チェックした項目を用語集に反映

# 2) 関門（ルーター）— 推奨の入口
cascadedlp --project myproj route design.md -o to_cloud.md     # 判定 + 通過・マスクなら送るテキスト
cascadedlp --project myproj route design.md -q "要約して" -o answer.md   # ローカル専用ならローカルモデルが答える
cascadedlp --project myproj confirm                            # 「確認」判定が出たら：保留リストに印を付けてから反映
cascadedlp audit                                               # 何がどこへ行ったか

# 3) 直接マスクして戻す
cascadedlp mask memo.md -o memo.masked.md                      # job id を出力
cascadedlp unmask answer.md --job <job_id> -o answer.restored.md
```

**MCP（Claude Code などからツールとして）**
```powershell
claude mcp add --scope user cascadedlp -- <リポジトリのパス>\.venv\Scripts\python.exe -m cascadedlp.mcp_server
```
- `cascadedlp-mcp.exe` ではなく `python.exe -m` で登録します。pip が作る署名なしの実行ファイルは、Windows のアプリケーション制御（スマート アプリ コントロールなど）に止められることがあります（`WinError 4551`）。
- リポジトリのフォルダーを移動・改名すると登録したパスが壊れます（`uv_spawn` エラー）。新しい場所で `pip install -e .[mcp]` で入れ直し、上のコマンドで登録し直します。

ツール：`route_file(path, question?, project?)`（推奨）· `mask_file(path, project?)` · `unmask_to_file(masked_text, job_id, out_path)` · `list_entities()`
用語集の草案づくり（`bootstrap`）は「何が核心か」の一覧なので MCP にはなく、CLI だけで行います。
パス・ファイル名・形式（md/json/txt/csv）は会話でその都度指定します。既定の許可範囲はユーザーフォルダー、仮名マップのフォルダー・`.ssh`・`.claude`・`AppData` などは常に遮断、上書きは禁止（[ADR-0013](docs/adr/0013-path-policy.md)）。

**Python API**
```python
from cascadedlp.gate import Gate
g = Gate()
r = g.mask_file("memo.txt")
answer = call_external_llm(r.masked_text)       # 外部には仮名化したテキストだけ
g.unmask_to_file(answer, r.job_id, "memo_answer.txt")
```

## ロードマップ
文書（設計書・ADR・構造説明）が先、コードはその次（[ADR-0015](docs/adr/0015-cascade-dlp-direction.md)）。

| 段階 | 内容 | 状態 |
|---|---|---|
| P0–P5 | 個人情報エンティティ：規則 + ローカル LLM の検出、表記をまたぐ連結、可逆の仮名化、Gate/CLI/MCP、ローカル翻訳・要約 | ✅ |
| C0 | 方向の再定義（PII マスカー → カスケード型 DLP）、改名 | ✅ |
| C1 | エンティティの拡張（`PROJECT` `COMPONENT` `ALGORITHM` `TERM` `SECRET`）+ 機微度 L0–L3 + 安全な説明 + プロジェクト用語集（[ADR-0016](docs/adr/0016-project-glossary.md)） | ✅ |
| C2 | 用語集のブートストラップ：ローカル LLM が「このプロジェクトだけの言葉」と別表記のまとまりを提案 → **人が機微度を確定**（[ADR-0017](docs/adr/0017-glossary-bootstrap.md)、ホールドアウト項目 10/10・誤った統合 0） | ✅ |
| C3 | 情報を保つマスキング：レベル別にそのまま / 説明付きの別名 `[COMPONENT_01: スケジューラ]` / トークン / 遮断 + 実験用の文脈縮小（一般化・文の削除） | ✅ |
| C6 | 測定：**効用 対 名前の漏えい 対 意味の漏えい** — マスキングは効用を損なわず名前を守るが意味は守れない → 意味の保護は L3 ルーティング（[ADR-0018](docs/adr/0018-utility-vs-leakage.md)、[ADR-0019](docs/adr/0019-semantic-leakage.md)） | ✅ |
| C4 | コード：L3 パスの読み取り禁止 + マスクしたミラー作業領域（コア関数はシグネチャと説明だけ）→ 変更分の逆写像 | 次の候補 |
| C5 | ルーター（クラウドに原文 / マスク / ローカルのみ / 遮断）+ 監査ログ（[ADR-0020](docs/adr/0020-router.md)） | ✅ |
| C7 | 関門判定の完成：**疑わしい項目はユーザーが確認**（保留 → ローカルの保留リスト → 記憶）、複雑度基準の拒否（[ADR-0021](docs/adr/0021-cascade-confirmation.md)） | ✅ |
| **D**（第 3 段階） | **設計の知識ベースとコアロジックの分離**：数千行の設計書をローカルが漏れなく抱え（節ツリー・エンティティ索引・BM25・送付範囲の台帳）、それを根拠にコアロジックを特定してコードから分離（[ADR-0023](docs/adr/0023-knowledge-base-direction.md)、[想定シナリオ](docs/scenario-knowledge.md)） | D0 ✅ · D1 から予定 |
| 後続 | **関門の強制装置**：今は Claude Code が関門ツールを通さずにファイルを直接読める（案内文に頼るだけ）。権限設定・フックで保護フォルダーの直接読み取りを止める | 後続課題 |

### これまでの主な発見（合成の架空プロジェクト 2 件、ローカルモデル基準）
| 方式 | 効用 | 名前の露出 | 意味の漏えい |
|---|---|---|---|
| 原文 | 基準 | すべて | 0.83–0.89 |
| **L2 トークン（既定）** | 原文と同じ | **0** | 0.89–0.94 |
| L2 + 文の一般化 | 約 45% 低下 | 0 | 0.44–0.83 |
| L2 + 文の削除 | ほぼ 0 | 0 | 0.39–0.44 |

→ **マスキングは名前・個人情報を効用を損なわずに守る。しかし「何をどうするか」（設計意図）は文単位で隠しても漏れる。** 意味が秘密なものは隠すのではなく**ローカルだけで処理（L3 ルーティング）**すべきで、そのためにルーター（C5）を作った。

その他の測定結果：
- 用語集の草案：初めて見る架空プロジェクトで正解 10 項目がすべて候補に挙がり、別の対象を誤って統合したもの 0（[ADR-0017](docs/adr/0017-glossary-bootstrap.md)）。
- 用語集の適用：用語の漏えい 0、過剰なマスク 0、復元はバイト一致（[ADR-0016](docs/adr/0016-project-glossary.md)）。
- 疑わしい項目の確認：用語集からわざと外した用語の 87%（ホールドアウト）〜93%（開発用）を関門が止めた。用語集が埋まっているときの空振りの停止は文書 5 件中 0〜2 件（[ADR-0021](docs/adr/0021-cascade-confirmation.md)）。

## 既知の限界
- **マスキングは意味を守れない。** 設計意図が秘密なら L3 にしてローカルだけで処理する。
- **関門はまだ迂回できる。** Claude Code は関門ツールを通さずファイルを直接読める。強制装置は後続課題。
- **疑わしい項目の確認は未知の用語をすべては止められない（7–13% は通る）。** 特に韓国語・日本語の用語を見落とす。用語集を先に埋めておくのが基本の防御線。
- **L3 を多めに指定するとクラウドが使えない。** L3 の用語一つが文書 5 件中 4 件に出て、大半がローカル専用になった — L3 は少数の項目だけに（[ADR-0020](docs/adr/0020-router.md)）。
- **長い文書で人名の検出がときどき揺れる。** 断片を小さく分けて大きく減らしたが（露出 10 → 1）0 ではない（[ADR-0018](docs/adr/0018-utility-vs-leakage.md)）。
- ローカル専用経路の答えはローカルモデル（8K コンテキスト）の品質。長い文書は先頭部分だけを使う。
- **すべての数値は分析者が作った合成データ基準。** 実文書でのパイロットはまだ行っていない。
- 漢字だけの名前は読みが曖昧（伊藤大翔 → hiroto? daisho?）→ 表記をまたぐ連結に失敗。
- 空白だけでつながった二人の名前（`정민호 김민준`）は一人に統合される。
- 住所の境界が不正確（ADDRESS 完全 F1 0.44–0.57）。
- 同じ表記の同姓同名は区別しない。
- 仮名化の結果（個人情報でない部分）は外部へ出る。**機微な文書は仮名化の結果を確認してから送ること。** このツールは個人情報保護を助ける補助手段であり、完全な検出を保証しない。

## 評価データについて
`data/eval/` の名前・住所・連絡先はすべて**作り物**です。メール・URL は予約ドメイン（`example.com/.jp/.org`）だけを使います。電話・ID 番号は形式だけ合わせた任意の数字で、実在の番号と一致したら偶然です。
