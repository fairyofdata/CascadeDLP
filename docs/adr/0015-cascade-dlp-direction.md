# ADR-0015 방향 전환: PII 마스커 → 캐스케이딩 DLP 레이어 (CascadeDLP)

- 날짜: 2026-09-30 · 상태: 채택 (사용자 결정). 이름 LocalPIIGate → **CascadeDLP**

## 맥락
사용자가 실제로 만들려는 것은 개인정보 마스커가 아니라, **제한된 로컬 자원(RTX 3070 한 장)과 클라우드 최상위 모델(Claude 등)을 나눠 쓰는 하이브리드 캐스케이딩 개발 환경을 안정적으로 운영하는 계층**이었다.
- 보호하고 싶은 것은 이름·전화번호만이 아니라 **프로젝트 고유 용어, 컴포넌트, 알고리즘, 설계 의도**다. 이것들은 일반명사로 쓰이기도 해서 규칙으로는 잡을 수 없다(`오케스트레이터`, `조율기`, `Adaptive Scheduler`).
- 전부 가리면 클라우드 모델이 맥락을 잃어 도움을 못 준다. 핵심 질문은 "무엇을 가릴까"가 아니라 **"얼마나 적게 가리고도 보호 목적을 달성할까"**(정보 보존)이다.
- 로컬 자원이 충분하면 가림 자체가 성능 손실이 된다. 이 계층의 가치는 **자원이 제한된 환경의 분담**에 있다.

## 결정
1. 보호 대상을 **민감 엔티티**로 일반화: PII는 여러 종류 중 하나. `PROJECT`, `COMPONENT`, `ALGORITHM`, `TERM`, `SECRET` 추가.
2. 엔티티마다 **민감도 레벨**(L0 공개 / L1 내부 / L2 핵심 / L3 외부 금지)과 **안전한 설명**(가려도 의미를 남기는 별칭).
3. **민감도는 LLM이 제안하고 사람이 확정**(사용자 선택). "무엇이 경쟁우위인가"는 모델이 알 수 없는 가치 판단이다. 확정 후 적용은 결정론. 미확정 후보는 보수적으로 처리.
4. 가림 강도는 레벨별로 다르게(그대로 / 설명형 별칭 / 불투명 토큰·요약 / 차단) — **정보 보존형 가림**.
5. 최종 형태는 요청마다 경로를 정하는 **라우터**: 클라우드 원문 / 클라우드 가림 / 로컬 모델만 / 차단 + 무엇이 나갔는지 감사 로그.
6. 순서는 **문서(설계서·ADR·구조 설명) 먼저, 코드는 그다음**(사용자 선택).

## 결과
- 지금까지 만든 것(규칙·로컬 LLM 탐지·교차 표기 연결·가역 가명화·Gate/MCP·평가 체계)은 그대로 1단계 기반이 된다. "식별 → 동일 대상 연결 → 치환" 파이프라인은 PII와 프로젝트 용어에 똑같이 쓰인다.
- PLAN의 "하지 않는 것: 코드 로직 탐지(기준 불명확)"는 범위 안으로 들어온다. 기준은 사람이 확정하는 용어집이 된다.
- 새 평가 축: **효용(가린 뒤에도 클라우드 모델이 과제를 해내는가) 대 유출(보호 용어·코드가 밖으로 나갔는가)**. 둘 다 결정론으로 측정.
- 이름 변경: 패키지 `cascadedlp`, 명령 `cascadedlp`·`cascadedlp-mcp`, 설정·맵 폴더 `~/.cascadedlp`, 환경변수 `CASCADEDLP_HOME`, MCP 서버 이름 `cascadedlp`(재등록 완료), GitHub `fairyofdata/CascadeDLP`. ADR 0001–0014의 `piigate` 표기는 당시 기록으로 그대로 둔다.
- 개발·평가는 계속 합성 데이터만(합성 가상 프로젝트). 실제 회사 코드는 이 세션에 넣지 않는다.
