# ADR-0010 홀드아웃과 과적합 표기 절차

- 날짜: 2026-09-30 · 상태: 채택

## 맥락
평가 세트·규칙·프롬프트·후처리를 모두 같은 쪽(분석자)이 만들었고, v2 후처리·연결 판정은 eval_v1 오류를 보고 고쳤다. 개발 세트 수치만으로는 믿을 수 없다.

## 결정
1. 새 세트(eval_v2)를 만든 뒤 **코드를 고정하고 한 번만 채점**. 고정 시점 해시 `results/frozen_code_eval_v2.sha256`, 원 출력 `results/eval_v2_run.log`.
2. 홀드아웃을 보고 코드를 고치면 그 세트의 이후 수치는 **'튜닝 후'** 로 표시하고 홀드아웃 수치와 섞지 않는다.
3. 개발 세트(v1) 회귀도 같이 확인(v3 수정 후 v1 변화 없음).
4. 파이프라인 버전(`PROMPT_VERSION`: v1→v2→v3)은 프롬프트뿐 아니라 후처리·규칙·판정 변경에도 올린다. 결과 파일 이름에 항상 포함(덮어쓰기 방지).

## 결과 (홀드아웃에서 드러난 것)
- **규칙이 과적합**: 전화 recall 1.0 → 0.4 (공백 휴대폰, 0120, 괄호 국번), 여권번호 미탐.
- **모델 선택이 바뀜**: 개발 세트에선 비슷했던 세 모델 중 qwen3.5:9b만 유지([ADR-0006](0006-local-model.md)).
- 실수 기록: 결과 파일 이름에 버전이 없던 규칙만 모드가 고정 시점 v2 결과를 한 번 덮어씀 → 원 로그로 보존, 이후 모든 모드에 버전 태그.
- eval_v3(사용자 작성)는 하지 않기로(사용자 판단). 다음 홀드아웃이 필요하면 다른 생성 방식(예: 다른 모델·템플릿)으로 만든다.
