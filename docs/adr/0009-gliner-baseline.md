# ADR-0009 GLiNER 기준선: 측정했고, 채택하지 않음

- 날짜: 2026-09-30 · 상태: 채택(기준선으로만 유지, 본체 미포함)

## 맥락
차별점 4: 기존 도구를 기준선으로 실측하고 모자란 곳만 만든다. `urchade/gliner_multi_pii-v1`(1.1GB, CPU). Python 3.14에서 설치됨, 단 토크나이저에 `sentencepiece`·`protobuf` 필요(requirements-optional에 추가).

## 결과
| | eval_v1 완전 F1 | 겹침 F1 | eval_v2 완전 F1 | 지연 |
|---|---|---|---|---|
| GLiNER만 | 0.479 | 0.873 | — | 55ms |
| 규칙+GLiNER | 0.593 | 0.910 | 0.526 | 57~108ms |
| 규칙+LLM (qwen3.5:9b) | 0.873 | 0.930 | 0.875 | 2.8s |

- GLiNER는 **공백 단위로 끊어** 일본어는 문장 전체(`ハン・ソユンさんから資料が届きました`), 한국어는 조사·직함까지(`박민재 과장`)를 한 스팬으로 잡는다. 겹침 점수는 좋아 보이지만 가명화하면 본문이 통째로 사라진다.
- 교차 표기 연결 기능 없음.

## 결정
한·일 혼용 문서엔 그대로 못 쓴다 → 본체에 넣지 않는다. `tools/gliner_baseline.py`와 `evaluate.py --gliner`로 비교용 유지. (빠른 1차 필터가 필요해지면 재검토.)
