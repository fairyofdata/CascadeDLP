# ADR-0017 C2 용어집 부트스트랩: LLM이 후보를 모으고, 사람이 md에서 확정한다

- 날짜: 2026-09-30 · 상태: 채택 (검토 방식·입력 범위·묶기 방식·측정 방식 모두 사용자 선택, 추천안)

## 맥락
C1([ADR-0016](0016-project-glossary.md))은 적힌 용어를 정확히 찾지만, **용어집을 채우는 일**이 진짜 난제다. 무엇이 핵심인지는 사람이 정해야 하므로 LLM은 후보·설명·묶음을 **제안**만 한다.

## 결정
- 입력: 프로젝트 **문서(md·txt)만**. 소스코드 식별자 스캔은 C4에서.
- 흐름 (`cascadedlp/bootstrap.py`, 버전 `b1`):
  1. 후보 추출 — 결정론: 코드 표기(`snake_case`·`CamelCase`), 영문 고유명(대문자 여러 단어, 앞 관사 제거). LLM: 한·일·영 프로젝트 고유어 + 한국어 짧은 설명. 원문에 없는 문자열은 버림.
  2. 걸러내기 — 기존 LLM 탐지로 **사람 이름** 제거. 공개 기술·일반어 판정(LLM)은 결정론 후보만 **제외**하고, LLM 추출 후보는 "공개어일 수 있음" 표시만(일반어처럼 생긴 `조율기`를 놓치지 않게).
  3. 같은 대상 묶기 — 표기 변형 정규화(결정론), 정의 패턴 `A(B)`(결정론), 음차(LLM이 영어 철자 추정 → 코드가 발음 비교로 판정), 번역 관계(LLM 제안 → **"확인 필요" 줄에만**, 묶지 않음). 한 문서에만 나온 긴 변형은 기존 후보의 "확인 필요"로.
  4. 검토 md — `## [ ] C001 · 용어` + kind·level(기본 2)·설명·표기·확인 필요·근거. **"확인 필요" 표기는 사람이 `표기` 줄로 옮겨야만 반영.**
  5. `apply-review` — 체크한 항목만 `glossary.json`에 confirmed로. 이미 있는 표기와 겹치면 그 항목에 표기만 보강.
- LLM 목록 응답은 **번호가 아니라 용어 자체를 되받아** 맞춘다(첫 실행에서 번호가 한 칸씩 어긋나 `ブレイドソルバー`가 Ledger Bridge에 붙고 `조율기`가 공개어로 제외된 버그의 수정).
- 🔴 후보 목록은 "무엇이 핵심인가"의 초안 → **CLI 전용**(MCP 미노출), 기본 저장 `~/.cascadedlp/projects/<프로젝트>/review.md`, 기존 검토 파일은 덮어쓰지 않음.
