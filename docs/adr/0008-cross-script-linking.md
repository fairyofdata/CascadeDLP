# ADR-0008 교차 표기 연결: LLM은 로마자 발음만, 판정은 코드

- 날짜: 2026-09-30 · 상태: 채택 (사용자 선택: "로마자 정규화 + 코드 비교"). v1 방식 폐기.

## 맥락
v1: 표기 44개를 LLM에 한 번에 주고 묶게 함 → qwen3:8b는 거의 전부를 한 사람으로 뭉침(쌍 P 0.058), 최고도 5/9. 가명화에서 가장 위험한 오류는 **두 사람이 한 토큰**이 되는 것.

## 결정
- `llm.romanize(표기)` → `{family, given, nationality}` 소문자 로마자 (표기마다 1회, 한국 이름은 개정 로마자+흔한 성 표기, 일본 이름은 장음 없는 헵번).
- `linking.group()` (결정론, union-find):
  - 성+이름 둘 다 있는 표기끼리: 성은 **별칭 표**(park/bak, lee/yi, jung/jeong/chong, yoon/yun, choi/che …) 또는 5자 이상이면 발음 유사도, 이름은 느슨한 발음 비교(eo→o, ou→o, ph→f, c→k …) 유사도 ≥ 0.8. LLM이 성/이름 칸을 뒤바꾸는 경우를 대칭으로 비교.
  - 성만/이름만: 정규화 후 **완전히 같은** 사람이 **딱 한 명**일 때만 연결(유사도로 붙이면 haru≈haruto, soyun≈doyun 오연결).
- 결과는 가명 맵 `romanized`에 캐시(새 표기만 LLM 호출).

- 한계: 한자 이름 읽기(伊藤大翔→daisho, 佐藤美咲→mizuki). 한자만으로는 원리적으로 모호.
- 비용: 표기당 약 2.7초(캐시 전).
