# ADR-0021 C7 관문 판정 완성: 의심 항목은 사용자 확인, 처리 못 하면 거부

- 날짜: 2026-10-03 · 상태: 채택 (보류 방식, 로컬 대기 파일 + CLI, 거부 기준 네 가지: 사용자 선택)

## 맥락
사용자가 정리한 흐름: **로컬 모델이 DLP 관문 → 감지되면 처리 / 감지 없으면 바로 클라우드 / 의심되면 사용자에게 확인 / 처리할 수 없으면 거부 → 클라우드 모델이 다룸 → 결과를 로컬에서 복원.**
[ADR-0020](0020-router.md)까지의 구현에는 "의심되면 확인"이 없었고(낯선 용어는 그냥 통과), 거부 기준이 L3·비밀키뿐이었다.

## 명명: 용어 두 가지 (2026-10-03 사용자와 정리)
이름의 착안은 처리 요구 수준에 따라 로컬과 클라우드를 나눠 쓰는 다른 프로젝트(흔히 말하는 LLM 캐스케이드: 싼 모델이 먼저 풀고 어려우면 비싼 모델로)에서 왔다. 그러나 DLP에서는 그 방식을 쓸 수 없다. **난이도로 넘기면 "어렵고 민감한" 문서가 클라우드로 올라간다.** 넘기는 기준은 민감도 하나여야 한다.

그래서 이 프로젝트의 캐스케이드는 **로컬 관문 안에** 있고, 용어를 둘로 나눠 쓴다.
- **탐지 캐스케이드**: `규칙(형식) → 사람이 확정한 용어집 → 로컬 LLM`. 값싸고 확실한 것부터, 앞 단계가 잡은 것은 뒤 단계가 뒤집지 못한다(`spans._SOURCE_RANK`). 분류기 캐스케이드의 전통적인 뜻과 같다. **이름 CascadeDLP의 "캐스케이드"는 이것만 뜻한다.**
- **관문 판정**: 탐지 결과로 문서를 어떻게 할지 정하는 다섯 가지 결론 — 통과 · 가림 · 확인 · 로컬 전용 · 거부(`router.route_text`). 이것은 캐스케이드라고 부르지 않는다.

처음에는 판정 쪽도 "판정의 캐스케이드"라고 불렀다가 분리했다(사용자 결정). 이유: "캐스케이드"는 이미 LLM 캐스케이드와 혼동되기 쉬운 말인데, 프로젝트 안에서까지 두 뜻으로 쓰면 내용이 아니라 용어 정의에 매몰된다. 판정 순서는 엄밀히 단계별 정책에 가깝기도 하다.

한 문장 정의: **로컬 관문이 탐지 캐스케이드로 민감한 것을 찾아 관문 판정을 내리고, 통과한 결과만 클라우드가 다루는 하이브리드 정보처리 레이어.** 성능·비용 최적화가 아니라 DLP임을 이름(`DLP`)과 README 제목에서 밝힌다.
민감도에 따라 처리 환경이 달라지는 것(L3는 로컬 모델, 나머지는 클라우드)은 이 정의와 상충하지 않고 관문 판정의 일부다.

## 후속 과제: 관문 강제 장치
지금 관문은 우회할 수 있다. Claude Code는 `route_file`을 거치지 않고 파일을 직접 읽을 수 있고, 현재는 MCP 안내문에만 의존한다. 권한 설정(보호 폴더 읽기 금지)이나 훅으로 강제하는 것은 후속 과제로 둔다(사용자 결정, 2026-10-03).

## 결정
- 새 판정 **`needs_confirmation`**: 용어집에도 허용 목록에도 없고 이미 가려지지도 않는 "프로젝트 용어처럼 생긴 말"(코드 표기·영문 고유명·로컬 LLM이 고유어로 뽑은 것 — C2 후보 추출 재사용)이 있으면 **문서를 보내지 않는다.**
- 확인은 **로컬에서만**: 의심 항목을 `~/.cascadedlp/projects/<프로젝트>/pending.md`(체크리스트)에 쌓고, 호출자(Claude)에게는 **건수와 파일 위치만** 알린다. 의심 용어 자체가 외부 LLM을 거치면 안 되기 때문.
  - `[x]` 보호 → 용어집에 confirmed로 추가(kind·level·설명 수정 가능) / `[o]` 일반어 → `allow.json` / `[ ]` 미정 → 계속 보류.
  - `cascadedlp --project <이름> confirm`으로 반영. **한 번 답한 것은 다시 묻지 않는다.**
- 프로젝트(용어집)가 지정되지 않은 문서와 규칙만 모드에서는 의심 검사를 하지 않는다(기준이 없으면 모든 고유명이 의심이 된다).
- **거부(`block`) 기준**: 비밀키(기존) · 원문에 토큰 모양 문자열(복원이 모호) · 의심 항목 20건 초과(용어집부터 만들라는 신호) · 300자 이상 문서에서 가릴 글자 비율 30% 이상(클라우드가 일할 수 없음). 임계값은 `config.json`의 `max_suspects`·`max_masked_ratio`.
- 판정 순서: 거부(비밀키·토큰 모양) → 로컬 전용(L3) → 거부(의심 과다) → 확인 → 거부(가릴 비율) → 통과/가림. 파이프라인 v7.

## 결과 (`tools/eval_suspects.py`)
정답 용어집에서 항목을 하나씩 빼고(leave-one-out) 그 용어가 나오는 문서를 라우팅 — "그 용어가 가려지지 않은 채 밖으로 나갔는가".

| | 개발용 Tessellane | 홀드아웃 Quillmere (코드 고정 후 1회) |
|---|---|---|
| 용어집이 다 찼을 때 헛멈춤 | 0/5 문서 | **2/5** (`Plant Sensor Analytics` 제목 문구, `RocksDB` 공개 기술) |
| 뺀 용어 사례 수 | 46 | 48 |
| 보류됨 (그 용어가 대기 목록에 오름) | 41 (41) | 35 (32) |
| 개인정보 층이 가림 | 2 | 7 |
| **그대로 나감** | **3 (7%)** | **6 (13%)** |

홀드아웃: `results/frozen_code_c7_holdout.sha256`, 원 출력 `results/c7_holdout_run.log`.
- 홀드아웃에서 더 나쁘다. 나간 6건 중 5건이 한국어 설계서·회의록의 한국어 용어(`퀼미어`, `웨프트 보드`, `새벽 스윕`, `블루 시프트`, `이중 창 보정`) — **로컬 LLM의 한국어 고유어 추출이 약하다.** 영문·코드 표기는 결정론 후보(대문자 고유명·snake_case)가 받쳐 주지만 한국어·일본어 용어는 LLM에만 의존한다.
- 보류 35건 중 3건은 그 용어가 아니라 같은 문서의 다른 의심 항목(헛멈춤) 때문에 멈춘 것이다.
- 헛멈춤 2건은 한 번 `[o]`로 표시하면 다시 묻지 않는다.

- 채점 기준을 한 번 바꿨다(둘 다 기록): 처음 기준 "정확히 그 표기가 대기 목록에 올랐나" = 개발용 40/46. 놓친 6건 중 3건은 실제로는 막힌 경우(포함하는 더 긴 말로 잡힘 1, 개인정보 층이 조직명으로 가림 2)라 "밖으로 나갔나" 기준으로 바꿨다 = 나간 것 3/46.
- 개발용에서 나간 3건도 문서에서 한 번 스치듯 나온 한국어 용어(`테셀레인`, `레벨3 파이프라인`, `골든 슬롯`).
- **결론: 관문은 낯선 용어의 87–93%를 막지만 전부는 아니다.** 용어집을 미리 채워 두는 것(C2 부트스트랩)이 기본 방어선이고, 의심 확인은 그 보완이다. "의심 확인이 있으니 용어집 없이 써도 된다"는 아니다.
- 다음 개선 후보(아직 안 함): 한국어·일본어 용어의 결정론 후보(조사 앞 명사구 반복, 가타카나 연속어), 후보 추출을 두 번 돌려 합집합.
- 테스트 139개: 보류 시 내용·용어를 호출자에게 주지 않음, 확인 후 통과, 미정 항목은 계속 보류·중복 없음, 프로젝트 없으면 검사 안 함, 과다 시 거부, 감사 로그에 용어 없음.
