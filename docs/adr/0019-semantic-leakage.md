# ADR-0019 의미 유출 측정: 가림은 이름을 지키지만 의미는 지키지 못한다 → 의미 보호는 라우팅(L3)으로

- 날짜: 2026-10-01 · 상태: 채택 (채점 = 키워드 결정론, 새 방식 = 문장 제거 + 로컬 일반화: 사용자 선택)

## 맥락
[ADR-0018](0018-utility-vs-leakage.md)에서 L1·L2 가림은 효용을 해치지 않았지만, 그 이유가 "문서가 역할을 설명해서 이름을 숨겨도 뜻이 남기 때문"이라면 **설계 의도가 새고 있다**는 뜻이다. 이를 숫자로 확인한다.

## 측정 설계 (`tools/eval_semantic.py`, `s1`)
- 보호 항목(컴포넌트·알고리즘·용어) 8개 × 프로젝트 2곳, 항목마다 "숨기고 싶은 사실" 2–3개(총 18개/곳)와 허용 키워드(한·영·일) — `gold.json`의 `secrets`.
- 공격자(로컬 qwen3.5:9b)에게 **그 항목이 나오는 문서들의 가린 버전**만 주고 "[ALGORITHM_01]은 무엇이고 무엇을 어떻게 하는가, 원래 이름은?"을 묻는다 → 사실별 키워드로 채점.
- **대조군**: 문서 없이 추측만 → 0/18, 1/18. 키워드 채점의 추측 잡음은 작다.
- 같은 가림 결과로 효용(질문 13개)도 잰다.
- 새 가림 방식(C3, `Gate.mask_text(l2_context=...)`, 파이프라인 v6):
  - `generalize`: L2 항목이 나오는 문장을 로컬 LLM이 '어떻게'(절차·수치·호출 관계·일정)를 빼고 다시 씀. 토큰을 잃으면 제거로 대신.
  - `drop`: L2 항목이 나오는 문장 제거. 마크다운 줄 구조는 유지.

## 결과
| 방식 | 효용 개발 / 홀드아웃 | 이름 노출 | **의미 유출** 개발 / 홀드아웃 | 이름 복원 |
|---|---|---|---|---|
| 원문 | 10 / 13 | 102 / 75 | 0.89 / 0.83 | — |
| L1 설명형 | 12 / 12 | 0 | 0.67 / 0.89 | 0 |
| L2 토큰 | 12 / 13 | 0 | **0.89 / 0.94** | 0 |
| L2 + 로컬 일반화 | 7 / 7 | 0 | 0.44 / 0.83 | 0 |
| L2 + 문장 제거 | **0 / 1** | 0 | **0.44 / 0.39** | 0 |
| (대조군: 문서 없음) | — | — | 0.06 / 0.00 | — |

1. **L1·L2 가림은 이름만 지킨다.** 의미 유출이 원문과 같은 수준(0.67–0.94)이다. 외부 모델은 이름 없이도 "무엇을 어떻게 하는지"를 거의 다 복원한다. 원래 이름은 한 번도 못 맞혔다.
2. **문장 단위로 줄여도 교환이 나쁘다.** 일반화는 효용을 약 45% 잃고도 의미 유출이 개발에서만 절반, 홀드아웃에선 거의 그대로. 문장 제거는 효용이 0에 가까워지는데도 유출이 약 40% 남는다.
3. **의미는 이름이 나온 문장에만 있지 않다.** 예: ADR 본문의 "실패 이벤트는 재시도 3회 후 dead-letter 큐로 보낸다"에는 이름이 없지만 제목·흐름으로 누구 얘기인지 알 수 있다(암묵적 언급·지시어·문서 구조). 문장 단위 처리로는 못 막는다. 이는 코파일럿 대화에서 짚은 "보호해야 하는 것은 문자열이 아니라 맥락 속 의미"를 수치로 확인한 것이다.

## 결정
- **가림(L1·L2)의 역할을 '식별자 보호'로 한정해 문서화한다.** 이름·개인정보·고객사명은 가림으로 충분하고 효용 손실이 없다. L1과 L2의 효용 차이가 없으므로 기본은 **L2**, 읽기 쉬움이 필요할 때 L1.
- **의미(설계 의도·알고리즘의 동작)가 비밀인 항목은 L3로 두고 라우팅으로 보호한다** — 그 항목이 나오는 문서는 클라우드로 보내지 않고 로컬 모델이 처리. 이 결론이 C5(라우터)의 근거다.
- `generalize`·`drop`은 코드에 남기되 기본값으로 쓰지 않는다(측정 도구·실험용).

## 한계
- 두 프로젝트·18개 사실·로컬 공격자. 클라우드 최상위 모델이 공격자라면 의미 유출은 더 높을 것이다(보수적 추정이 아니라 낙관적 추정).
- 문서가 역할을 친절히 설명하는 설계서 스타일이다. 설명이 적은 문서(코드 위주)에선 결과가 다를 수 있다.
- 키워드 채점은 표현이 다르면 놓친다(원문도 0.83–0.89로 1.0이 아님) → 절대값보다 방식 간 비교로 볼 것.
