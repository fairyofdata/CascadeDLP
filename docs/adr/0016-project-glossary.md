# ADR-0016 C1 프로젝트 용어집: 사람이 적고, 기계가 정확히 찾는다

- 날짜: 2026-09-30 · 상태: 채택 (위치·형식·프로젝트 식별·레벨 규칙 모두 사용자 선택, 추천안)

## 맥락
캐스케이딩 DLP([ADR-0015](0015-cascade-dlp-direction.md))에서 보호하려는 "이 프로젝트에서만 특별한 말"(`조율기`, `Adaptive Scheduler`)은 일반명사로도 쓰여 규칙으로 못 잡고, 무엇이 핵심인지는 모델이 알 수 없는 가치 판단이다.

## 결정
- **용어집**: `~/.cascadedlp/projects/<프로젝트>/glossary.json` (저장소 밖, MCP가 항상 못 읽는 폴더). **"무엇이 핵심인가"의 목록이라 가명 맵보다 민감**하게 다룬다.
- **형식**: JSON. 항목 = `id`(KIND_01), `kind`(PROJECT·COMPONENT·ALGORITHM·TERM·ORG·PERSON·SECRET), `level`(0–3), `surfaces`(한·일·영 표기), `alias`(안전한 설명), `status`(confirmed/proposed).
- **레벨별 처리** (`Entry.render`, `Gate.mask_text`):

| 레벨 | 밖으로 나가는 모양 |
|---|---|
| L0 공개 | 원문 그대로 (겹침 정리에는 참여해 LLM이 그 자리를 가리지 못하게 함) |
| L1 내부 | `[COMPONENT_01: 작업 우선순위 스케줄러]` — 이름만 숨기고 의미는 남김 |
| L2 핵심 | `[ALGORITHM_02]` — 의미까지 숨김 |
| L3 외부 금지 | 클라우드용 텍스트를 만들지 않음(blocked). 안내에는 항목 id만, 용어 자체는 알리지 않음 |

  - `status`가 confirmed가 아니면 실효 레벨을 최소 L2로(보수적).
  - 기존 개인정보는 L2와 같음(불투명 토큰).
- **매칭**(결정론): 표기를 단위로 쪼개(공백·`_`·`-`·가운뎃점·CamelCase) 사이 구분자를 허용하는 정규식, 대소문자 무시. 영문으로 시작·끝나면 단어 경계 → `adaptive_scheduler`·`AdaptiveScheduler`·`ADAPTIVE SCHEDULER`는 잡고 `adaptive scheduling`·`Atlassian`은 안 잡음. 긴 표기 우선.
- **우선순위**: 형식 규칙 > 용어집 > LLM 추정 (`spans._SOURCE_RANK`).
- **복원**: 토큰 정규식이 `[X_01: 설명]`도 인식하고 **id로 복원** → 외부 LLM이 설명을 바꿔 쓰거나 빼도 복원된다.
- **프로젝트 식별**: `config.json`의 `projects: {이름: [폴더…]}` 매핑으로 자동 + CLI `--project` / MCP `project` 인자로 직접 지정(우선). 이름은 영문·숫자·`_`·`-`만(경로 탈출 방지).
- **SECRET 규칙** 추가: 개인 키 블록, `sk-`·`ghp_`·`github_pat_`·`AKIA`·`xox?-`·`hf_`·`AIza` 접두 형식.
- 파이프라인 버전 v4. CLI `glossary-check <프로젝트>`로 형식 점검(중복 표기, L1인데 설명 없음 등).
